## Метод

### Трекинг доски: монотонность накопления чернил

Основная проблема — выбрать из ~7000 кадров те несколько десятков, где записанное
на доске **завершено**. Обычное покадровое сравнение (SSIM, гистограммы,
перцептивные хеши) даёт симметричную меру «кадр изменился» и не различает два
принципиально разных события: дописали следующую строку (новое состояние доски
начинать **нельзя**) и стёрли доску или переключили слайд (**нужно**).

Здесь разность между бинарными масками чернил раскладывается на направленные
компоненты:

```
added   = |cur ∧ ¬prev| / N        появилось чернил
removed = |prev ∧ ¬cur| / N        исчезло чернил
```

Пока лектор пишет, `removed ≈ 0`, а `added` растёт. Новое состояние доски
открывается при `removed > tau_erase` (содержимое разрушено) или
`added > tau_jump` (содержимое появилось разом — новый слайд). Внутри состояния
опорным берётся кадр с максимальным покрытием чернилами — то есть последний
момент перед стиранием, когда доска максимально заполнена.

Две дополнительные детали, без которых это не работает на реальных записях:

* **Маска нестабильности.** Врезка с веб-камерой, курсор, полоса прогресса
  меняются почти в каждом кадре, а содержательные записи держатся десятки секунд.
  Пиксели с частотой изменения выше квантили `static_quantile` исключаются —
  детектор лица или ручная разметка прямоугольников не нужны.
* **ROI по накопленным чернилам.** Область письма ищется не по физической рамке
  доски (её может не быть вовсе), а как наименьшее окно, содержащее `roi_keep`
  массы накопленных за лекцию чернил. Это заодно отрезает субтитры, ватермарки и
  чёрные поля.

### Хранение масок

Стадия трекинга держит маску чернил на каждую секунду лекции. Маски хранятся
упакованными по битам (`utils.imaging.PackedMasks`), а карта нестабильности
считается попарным проходом со счётчиком на пиксель. Расход памяти —
около 0.062 МБ на кадр при ширине 960 (≈0.3 ГБ на 80 минут) вместо ≈2 МБ
на кадр в варианте, где все маски складывались в один массив.

### Чтение доски

Кадр отправляется VLM вместе с расшифровкой речи за это же время. Рукописный
текст неоднозначен ($\xi$ или $\zeta$, индекс $i$ или $l$), но лектор проговаривает
символ вслух ровно тогда, когда его пишет, — обусловливание на речь снимает
существенную часть таких случаев бесплатно.

Специализированные распознаватели формул (`pix2tex`, `texify`) сюда не подходят:
они хороши на вырезанной одиночной формуле, а доска — это смешанный макет из
текста, нескольких формул и наброска с подписанными осями.

### Сегментация: слияние двух дорожек

Границы состояний доски точны по времени, но пересегментируют — один вывод может
пережить три стирания. Лексические границы (провалы связности словаря, в духе
TextTiling) находят смену темы, но размыты на десятки секунд. Каждый промежуток
между репликами получает оценку

```
score(i) = w_visual · visual(i) + w_lexical · depth(i)
```

где `visual(i)` — гауссов приор вокруг начала состояния доски, `depth(i)` —
нормированная глубина провала связности. Границы выбираются жадно по убыванию
оценки при ограничении на минимальную длину раздела; слишком длинные разделы
принудительно дробятся, чтобы не переполнять контекст генерации.

### Генерация и проверка

Разделы генерируются по отдельности, волнами: внутри волны параллельно, между
волнами — с передачей заголовков уже написанных разделов, чтобы не было повторов.
Каждый фрагмент проходит синтаксический валидатор LaTeX (баланс `$`, `{}`, `\[`,
парность окружений, отсутствие преамбульных команд). Неисправимый фрагмент
оборачивается в видимый блок с пометкой — потерять вёрстку одного раздела
допустимо, не собрать PDF после двухчасового прохода — нет.

## Оценка

Демонстрации недостаточно, нужны числа. Там, где есть эталонный конспект,
написанный человеком, считаются:

| метрика | что показывает |
|---|---|
| recall / precision формул | восстановлена ли математика (формулы нормализуются: `\frac 1n` = `\frac{1}{n}`) |
| покрытие терминов | не потеряно ли важное |
| `Pk`, `WindowDiff` | качество разбиения на разделы |

```bash
python scripts/evaluate.py runs/<hash>/output/notes.tex \
    --reference notes/lecture04.tex \
    --ablation runs/<hash>/lecture.json
```

Флаг `--ablation` считает те же метрики для базовой линии «только расшифровка
речи». Разница между этими двумя числами и есть измеренный вклад визуальной
ветки — главный количественный результат работы.

Пороги зрения калибруются по 10–15 вручную отмеченным сменам доски:

```bash
python scripts/calibrate_vision.py lecture.mp4 --marks marks.txt
```

## Тесты и эксперименты

```bash
pytest -q                        # 70 тестов, без видео и без обращений к API
python scripts/smoke_test.py     # сквозной прогон на синтетической лекции
python scripts/benchmark.py      # время и память локальных стадий -> bench_results/*.csv
```

Тесты зрения работают на синтетических кадрах: проверяются ровно те свойства, на
которых держится метод (письмо добавляет чернила и не удаляет их; стирание
удаляет; мигающая врезка попадает в маску нестабильности).

## Ограничения

* Рисунки, графики и схемы не переносятся в TikZ — вместо них плейсхолдер
  `\bropilotfigure{описание}`. Автоматическая векторизация чертежей — отдельная
  задача, в объём не входит.
* Пороги `tau_erase` / `tau_jump` зависят от записи; при смене лектора или
  разрешения их нужно перекалибровать.
* Качество конспекта ограничено качеством ASR: на записях с плохим звуком
  деградирует всё, что ниже по пайплайну.
* Система не проверяет математическую корректность того, что сказал лектор, и не
  исправляет его оговорки — по построению переносит источник как есть.

## Источники и заимствования

Работа опирается на следующие источники (полный список — в пояснительной записке):

* Radford et al., *Robust Speech Recognition via Large-Scale Weak Supervision*
  (Whisper) — модель ASR;
* Hearst, *TextTiling: Segmenting Text into Multi-paragraph Subtopic Passages* —
  идея лексической связности и метрика глубины провала;
* Beeferman, Berger, Lafferty — метрика `Pk`; Pevzner & Hearst — `WindowDiff`;
* H. Housen, *lecture2notes* — постановка задачи «лекция → конспект» и
  разбор подводных камней извлечения слайдов (метод здесь другой:
  направленная разность масок чернил вместо удаления рамок и классификации кадров);
* курс *Deep Learning in Audio* (markovka17/dla) — структура проекта,
  конфигурация и организация экспериментов.
